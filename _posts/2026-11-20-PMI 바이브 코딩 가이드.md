# 바이브 코딩 유의 사항: 운영 서버 배포 전 필수 확인

대 AI 시대, 누구나 원하는 앱을 만드는 날이 왔습니다.

명령어 몇 줄로 내가 원하는 프로그램을 만들 수 있다니 정말 좋은 세상입니다.

혼자 사용할때는 좋지만 이제 내 서비스를 외부에 공개해야 할 때 놓치는 부분들이 발생하여 이를 미연에 방지하고자 가이드를 작성해봅니다.

> **AI로 만든 코드를 그대로 실제 운영 서버에 배포하면 보안에 매우 취약한 상태입니다.** 화면이 정상적으로 동작해도 비밀값 노출, 인증 누락, 해킹 공격에 무방비인 경우가 대부분입니다.

이 문서는 비개발자가 바이브 코딩으로 만든 결과물을 운영 서버에 배포하기 전에 반드시 지켜야 할 유의 사항입니다. 

**예시 기술 스택**: JavaScript(Node.js·React), Python / MongoDB, PostgreSQL / 개발 PC: Windows, macOS (운영 서버: Linux)

## 내 코드 그대로 운영 서버에 배포하면 위험한 이유

AI는 "동작하는 코드"를 목표로 작성하며, 요청하지 않은 보안 처리는 대부분 생략합니다. 

내 PC나 사내 테스트에서는 문제가 드러나지 않지만, 운영 서버는 인터넷에 공개되어 누구나 접근하고 공격할 수 있습니다.

| 바이브 코딩에서 흔한 상태 | 운영 서버에서 일어날 수 있는 일 |
| --- | --- |
| 코드나 브라우저에 API 키 노출 | 키 도용으로 외부 API 요금 폭증, 클라우드 계정 탈취 |
| 로그인·권한 확인이 없는 API | 누구나 고객 데이터를 조회·수정·삭제 |
| 입력값 검증 없음 | SQL·NoSQL Injection으로 DB 탈취·삭제 |
| 운영 DB에 직접 연결해 개발 | 실수 한 번으로 실제 데이터 손상 |
| 에러 메시지·디버그 모드 노출 | 서버 내부 구조가 공격자에게 노출 |

개인정보가 유출되면 회사는 신고·통지 의무와 과징금 등 법적 책임을 지게 됩니다.

**운영 배포 원칙**

- 바이브 코딩 결과물은 기본적으로 **개인·사내 테스트용**입니다. 외부 공개나 실제 고객 데이터를 다루는 운영 배포는 **개발팀 보안 검토를 통과한 경우에만** 가능합니다.
- 개발 중에는 운영 DB나 실제 고객 데이터를 사용하지 않고, 테스트용 데이터를 사용합니다.
- 이 문서의 체크리스트를 모두 통과해도 개발팀 보안 검토를 대신할 수 없습니다.

## 핵심 원칙 4가지

1. **비밀값은 코드에 넣지 않는다.** DB 접속 정보, API 키는 항상 환경변수로 관리합니다.
2. **내 PC에서 빌드·실행이 성공한 것만 요청한다.** "일단 올려보고 고치기"는 금지입니다.
3. **데이터가 쌓였을 때를 생각한다.** 테이블 구조와 인덱스는 개발팀과 먼저 상의합니다.
4. **모든 입력은 위험하다고 가정한다.** 로그인, 권한, 입력 검증은 기본값입니다.

> AI가 만든 코드는 "동작하는 코드"이지 "안전한 코드"가 아닙니다. 결과물에 대한 1차 책임은 요청자에게 있습니다.

## 1. 비밀정보 관리 (하드코딩 금지)

DB 비밀번호나 API 키가 코드에 들어가면 Git에 영구히 남고, 유출 시 키 폐기·교체 비용이 발생합니다. 비밀값은 반드시 `.env` 파일로 분리합니다.

**잘못된 예**

```javascript
// ❌ JavaScript: 접속 문자열에 비밀번호 포함
const client = new MongoClient('mongodb://admin:P@ssw0rd@prod-db:27017');
const OPENAI_KEY = 'sk-abc123...';
```

```python
# ❌ Python: 코드에 비밀번호
conn = psycopg2.connect(host="prod-db.company.com", password="P@ssw0rd123")
```

**올바른 예**

```bash
# .env (Git에 올리지 않음)
MONGODB_URI=mongodb://...
DATABASE_URL=postgresql://...
OPENAI_API_KEY=...
```

```javascript
// ✅ JavaScript (Node.js)
require('dotenv').config();
const client = new MongoClient(process.env.MONGODB_URI);
```

```python
# ✅ Python
import os
from dotenv import load_dotenv

load_dotenv()
conn = psycopg2.connect(os.environ["DATABASE_URL"])
```

**지켜야 할 것**

- `.env`는 `.gitignore`에 반드시 추가하고, 키 이름만 적은 `.env.example`을 함께 제공합니다.
- **프론트엔드(React 등 브라우저 코드)에는 비밀 키를 절대 넣지 않습니다.** `VITE_`, `REACT_APP_`, `NEXT_PUBLIC_` 변수는 누구나 볼 수 있습니다. 외부 API 호출은 백엔드 서버를 거치게 합니다.
- Jupyter 노트북(`.ipynb`)은 셀 출력에 키나 접속 정보가 남기 쉽습니다. 커밋 전에 출력을 지웁니다.
- 실수로 키를 커밋했다면 파일만 지우지 말고 **즉시 개발팀에 알려 키를 폐기**합니다. Git 이력에 남아 있기 때문입니다.
- 운영 DB 접속 정보는 개발팀이 배포 환경에 직접 설정합니다. 요청자는 운영 DB 정보를 받지 않습니다.

## 2. 배포 전 검증 (수정-배포 반복 방지)

배포 후 오류의 대부분은 "내 PC에서는 됐는데" 상황입니다. 아래 순서를 모두 통과한 뒤에만 배포를 요청합니다.

| 단계 | JavaScript (Node.js·React) | Python |
| --- | --- | --- |
| 1. 의존성 고정 | `package-lock.json` 커밋 | `requirements.txt`에 버전까지 고정 (`pip freeze`) |
| 2. 클린 설치 | `node_modules` 삭제 후 `npm ci` | 새 가상환경 생성 후 `pip install -r requirements.txt` |
| 3. 빌드·실행 | `npm run build` 후 `npm start` 확인 (`npm run dev`만으로는 부족) | 서버 실행 명령으로 기동 확인 |
| 4. 코드 검사 | `npx eslint .` 에러 0건 | `ruff check .` 에러 0건 |
| 5. 런타임 버전 명시 | `.nvmrc` 또는 `package.json`의 `engines` | `.python-version` 또는 README에 버전 기재 |

OS별 명령어 차이(폴더 삭제, 가상환경 활성화 등)는 3장을 참고합니다.

이어서 공통으로 확인합니다.

- **환경변수 점검**: 새로 추가한 환경변수를 `.env.example`에 모두 적었는지 확인합니다. 배포 오류의 흔한 원인입니다.
- **주요 기능 직접 테스트**: 정상 입력뿐 아니라 빈 값, 잘못된 값, 로그아웃 상태에서도 눌러 봅니다.

**자주 놓치는 환경 차이**

- `localhost` 주소나 포트를 코드에 직접 적은 경우 → 환경변수로 분리
- 전역 설치 패키지에 의존 → 내 PC에만 있는 패키지는 서버에 없음, 반드시 의존성 파일에 추가
- 로컬 DB에만 있는 테이블·컬렉션·데이터에 의존 → 마이그레이션 또는 초기화 스크립트로 제공
- 경로, 파일명 대소문자, 줄바꿈, 인코딩 등 OS 차이 → 3장 참고

**오류가 났을 때**: AI에게 "고쳐줘"만 반복하지 말고, 에러 메시지 전문과 재현 방법을 개발팀에 공유합니다. 같은 오류로 2회 이상 재배포하면 개발팀 리뷰를 먼저 받습니다.

## 3. 개발 환경 차이 (Windows·macOS)

개발 PC는 Windows·macOS지만 운영 서버는 Linux입니다. \*\*기준은 "내 PC에서 되는가"가 아니라 "Linux 서버에서 되는가"\*\*입니다. 한쪽 OS에서만 동작하는 코드는 배포 후 오류가 납니다.

| 항목 | Windows | macOS | 대응 방법 |
| --- | --- | --- | --- |
| 경로 구분자 | `\` | `/` | 경로 문자열 직접 조립 금지, JS `path.join()`, Python `pathlib.Path` 사용 |
| 파일명 대소문자 | 구분 안 함 | 기본 구분 안 함 | 서버(Linux)는 구분함, import 경로를 실제 파일명과 정확히 일치 |
| 줄바꿈 | CRLF | LF | `.gitattributes`로 LF 통일 |
| 파일 인코딩 | Python `open()` 기본값이 cp949라 한글 깨짐 | UTF-8 | 파일 읽기·쓰기에 `encoding="utf-8"` 명시 |
| Python 실행 | `python` 또는 `py` | `python3` | 가상환경 활성화 후 `python`으로 통일 |
| 가상환경 활성화 | `.venv\Scripts\activate` | `source .venv/bin/activate` | README에 두 OS 명령 모두 기재 |
| 폴더 삭제 | `Remove-Item -Recurse -Force node_modules` | `rm -rf node_modules` | npm 스크립트에는 `rimraf` 같은 OS 공통 도구 사용 |
| npm 스크립트 환경변수 | `NODE_ENV=production node app.js` 실패 | 정상 동작 | `cross-env` 사용 또는 `.env`로 처리 |
| 스크립트 파일 | `.bat`, `.ps1` | `.sh` | 배포용 스크립트는 Linux(`.sh`) 기준으로 작성하고 개발팀 확인 |

**경로 처리 예시**

```javascript
// ❌ Windows에서만 동작
const file = __dirname + '\\uploads\\' + name;

// ✅ 모든 OS에서 동작
const file = path.join(__dirname, 'uploads', name);
```

```python
# ✅ 모든 OS에서 동작 (경로 + 인코딩)
from pathlib import Path

file = Path(__file__).parent / "uploads" / name
text = file.read_text(encoding="utf-8")
```

**프로젝트에 넣어 둘 설정 파일**

```bash
# .gitattributes : 줄바꿈을 LF로 통일
* text=auto eol=lf
*.bat text eol=crlf

# .gitignore : OS가 만드는 파일 제외
.DS_Store
Thumbs.db
```

**자주 겪는 문제**

- **`.env` 파일이 안 보이거나 `.env.txt`로 저장됨**: 점(.)으로 시작하는 파일은 숨김 처리됩니다. macOS Finder는 `Cmd + Shift + .`, Windows 탐색기는 \[보기\] → \[숨긴 항목\]과 \[파일 확장명\]을 켭니다. Windows 메모장은 `.env.txt`로 저장하므로 VS Code 등 코드 편집기를 사용합니다.
- **Python 패키지 설치 오류**: 일부 패키지는 OS·CPU별로 설치 방식이 다릅니다. 에러 메시지와 OS 정보를 함께 개발팀에 공유합니다.

## 4. DB 설계 (구조와 인덱스)

데이터 100건에서는 빠르던 화면이 10만 건에서 멈추는 일이 생깁니다. **새 테이블·컬렉션을 만들거나 구조를 바꿀 때는 개발 전에 개발팀과 먼저 상의**합니다.

**공통 원칙**

- 모든 데이터에 생성·수정 시각(`created_at`, `updated_at`)을 둡니다.
- 운영 DB를 직접 수정하지 않습니다. 구조 변경은 마이그레이션 파일이나 스크립트로 제출합니다.
- 같은 정보를 여러 곳에 중복 저장하지 않습니다. (예: 주문마다 회원 이름을 복사하지 말고 회원 ID로 연결)

**DB별 주의사항**

| 항목 | PostgreSQL | MongoDB |
| --- | --- | --- |
| 구조 정의 | 기본키, 외래키, `NOT NULL` 제약을 반드시 지정 | "스키마가 없다"고 마음대로 저장 금지, Mongoose 스키마 또는 `$jsonSchema` 검증 사용 |
| 구조 변경 | 마이그레이션 도구 사용 (Python: Alembic, JS: Prisma·Knex 등) | 필드 추가·변경 시 기존 문서 변환 스크립트 제공 |
| 데이터 타입 | 날짜는 `timestamptz`, 금액은 `numeric` | 같은 필드는 항상 같은 타입 (날짜를 문자열과 Date로 섞지 않기) |
| 관계 표현 | 테이블 분리 + 외래키 | 함께 조회하는 소량 데이터는 내장, 계속 늘어나는 데이터는 별도 컬렉션 |
| 주의 | 대용량 테이블에 컬럼 추가·변경은 개발팀 협의 | 문서 안 배열을 무한히 늘리지 않기 (문서당 16MB 제한) |

**인덱스가 필요한 경우**

조건 검색, 정렬, 조인(`$lookup`)에 자주 쓰이는 필드에는 인덱스를 추가합니다.

```sql
-- PostgreSQL: 사용자별 최신순 주문 조회용
CREATE INDEX idx_orders_user_created ON orders (user_id, created_at DESC);
```

```javascript
// MongoDB: 같은 용도
db.orders.createIndex({ userId: 1, createdAt: -1 });
```

인덱스가 실제로 쓰이는지는 PostgreSQL `EXPLAIN ANALYZE`, MongoDB `.explain('executionStats')`로 확인합니다. `Seq Scan`(대용량 테이블)이나 `COLLSCAN`이 보이면 인덱스가 없는 것입니다.

**쿼리 주의사항**

- 목록 조회는 반드시 **페이지네이션**을 적용합니다. (PostgreSQL `LIMIT`, MongoDB `.limit()`) 전체 조회 금지.
- 반복문 안에서 쿼리를 호출하지 않습니다(N+1 문제). `JOIN`, `$in`, `$lookup`으로 한 번에 가져옵니다.
- 필요한 컬럼·필드만 조회합니다. (`SELECT *` 대신 컬럼 지정, MongoDB는 projection 사용)

## 5. 웹 보안 기본 사항

AI는 요청하지 않으면 보안 코드를 거의 넣지 않습니다. 아래 항목은 모든 서비스에 기본 적용합니다.

| 항목 | 위험 | 적용 방법 |
| --- | --- | --- |
| 인증 | 누구나 API 호출 가능 | 모든 API에 로그인 확인 적용 (Express 미들웨어, FastAPI `Depends` 등), 공개 API만 예외 |
| 인가(권한) | 남의 데이터 조회·수정 | 요청한 사용자가 해당 데이터 소유자인지 서버에서 확인 |
| 입력 검증 | 잘못된 값, 악성 값 저장 | JS: `zod`·`joi`, Python: `pydantic`으로 타입·길이·허용 필드 검증 |
| SQL Injection | PostgreSQL 데이터 탈취·삭제 | 문자열로 쿼리 조립 금지, 파라미터 바인딩 또는 ORM 사용 |
| NoSQL Injection | MongoDB 조건 우회 (로그인 우회 등) | 요청 값을 쿼리 객체에 그대로 넣지 않기, 값이 문자열·숫자인지 검증 |
| XSS | 사용자 화면에 악성 스크립트 실행 | `innerHTML`, React `dangerouslySetInnerHTML`, Jinja2 `\|safe` 사용 금지 (불가피하면 DOMPurify 등으로 정제) |
| CORS | 다른 사이트에서 API 호출 | `origin: '*'` 금지, 허용 도메인 명시 |
| 토큰 저장 | 토큰 탈취 | `localStorage` 대신 `httpOnly` 쿠키 사용 |
| 에러·디버그 노출 | 내부 구조 노출 | 운영 환경에서 스택 트레이스 응답 금지, Flask·Django `DEBUG` 끄기 |

**SQL Injection 예시 (PostgreSQL)**

```python
# ❌ 위험: 입력값이 그대로 쿼리에 들어감
cur.execute(f"SELECT * FROM users WHERE email = '{email}'")

# ✅ 안전: 파라미터 바인딩
cur.execute("SELECT * FROM users WHERE email = %s", (email,))
```

```javascript
// ✅ JavaScript (node-postgres)
await pool.query('SELECT * FROM users WHERE email = $1', [email]);
```

**NoSQL Injection 예시 (MongoDB)**

```javascript
// ❌ 위험: password에 { "$ne": null }이 들어오면 비밀번호 없이 로그인됨
users.findOne({ email: req.body.email, password: req.body.password });

// ✅ 안전: 문자열인지 먼저 검증 (express-mongo-sanitize 등 병행)
if (typeof req.body.email !== 'string') return res.status(400).end();
```

**인가 누락 예시**: `/orders/:id` API가 로그인만 확인하고 주문 소유자를 확인하지 않으면, URL의 ID만 바꿔 다른 사람의 주문을 볼 수 있습니다. 가장 흔한 취약점입니다.

**그 외**

- 비밀번호는 평문 저장 금지, `bcrypt`·`argon2`로 해시합니다.
- 파일 업로드는 확장자·크기를 제한하고, 업로드 파일을 실행 가능한 경로에 저장하지 않습니다.
- 개인정보(이름, 연락처, 주민번호 등)를 다루는 기능은 개발 시작 전에 개발팀·보안 담당자와 협의합니다.
- 출처를 알 수 없는 패키지를 설치하지 않고, `npm audit`·`pip-audit`으로 취약점을 확인합니다.

## 6. AI에게 요청할 때 쓰는 프롬프트

AI는 시키는 만큼만 합니다. 작업 시작 시 아래 문구를 프롬프트(또는 `CLAUDE.md` 같은 프로젝트 규칙 파일)에 넣어 두면 대부분의 문제를 예방할 수 있습니다.

```markdown
## 프로젝트 규칙
- 기술 스택: JavaScript(Node.js, React) 또는 Python / DB: MongoDB, PostgreSQL
- 개발 PC는 Windows 또는 macOS, 운영 서버는 Linux이므로 세 환경 모두에서 동작하게 작성할 것
- 경로는 문자열로 조립하지 말고 path.join()(JS) 또는 pathlib(Python)을 사용할 것
- 파일 읽기·쓰기에는 encoding="utf-8"을 명시할 것
- npm 스크립트에 rm, cp 같은 OS 전용 명령을 쓰지 말고 rimraf, cross-env 등을 사용할 것
- import 경로는 실제 파일명과 대소문자까지 일치시킬 것
- API 키, DB 접속 정보 등 비밀값은 절대 코드에 쓰지 말고 환경변수(.env)로 분리할 것
- 새 환경변수를 추가하면 .env.example에도 추가할 것
- 프론트엔드 코드에는 비밀 키를 넣지 말 것
- 의존성은 package-lock.json / requirements.txt에 버전까지 고정할 것
- 모든 API에 인증을 적용하고, 데이터 소유자 확인(인가)을 포함할 것
- 요청 데이터는 zod(JS) 또는 pydantic(Python)으로 검증할 것
- PostgreSQL은 파라미터 바인딩을 사용하고 문자열로 SQL을 조립하지 말 것
- MongoDB 쿼리에 요청 값을 그대로 넣지 말고 타입을 먼저 검증할 것
- 목록 API에는 페이지네이션을 적용할 것
- 자주 조회하는 필드에는 인덱스를 추가할 것
- 로컬 경로, localhost 주소를 코드에 직접 쓰지 말 것
```

**작업을 마친 후 점검 요청**

> 이 코드가 데이터 10만 건 이상에서도 문제없이 동작하는지 DB 쿼리와 인덱스를 검토해줘.

## 7. 배포 요청 전 최종 체크리스트(선택사항)

아래 항목을 모두 확인한 뒤 배포를 요청합니다. 하나라도 해당하지 않으면 개발팀에 먼저 문의합니다. 체크리스트 통과는 최소 조건이며, 운영 배포는 개발팀 보안 검토 후 진행됩니다.

**비밀정보**

- [ ] 코드에 비밀번호, API 키, 토큰, DB 주소가 없다
- [ ] `.env`가 `.gitignore`에 포함되어 있고, `.env.example`이 최신이다
- [ ] 프론트엔드 코드에 비밀 키가 없다

**빌드·테스트**

- [ ] 의존성이 `package-lock.json` / `requirements.txt`에 버전까지 고정되어 있다
- [ ] 클린 설치(`npm ci` / 새 가상환경) 후 빌드·실행이 정상이다
- [ ] `eslint` / `ruff` 검사를 통과한다
- [ ] 정상·예외 입력으로 주요 기능을 직접 테스트했다

**OS 호환성**

- [ ] 경로를 문자열로 조립한 곳이 없다 (`path.join()` / `pathlib` 사용)
- [ ] 파일 읽기·쓰기에 `utf-8` 인코딩을 명시했다
- [ ] import 경로가 실제 파일명과 대소문자까지 일치한다
- [ ] `.gitattributes`로 줄바꿈이 LF로 통일되어 있고, `.DS_Store`·`Thumbs.db`가 커밋되지 않았다
- [ ] npm 스크립트에 OS 전용 명령(`rm`, `cp`, `set` 등)이 없다

**DB**

- [ ] 테이블·컬렉션 추가·변경 사항을 개발팀과 사전 협의했다
- [ ] 구조 변경은 마이그레이션 파일 또는 변환 스크립트로 포함되어 있다
- [ ] 목록 조회에 페이지네이션이 있고, 자주 조회하는 필드에 인덱스가 있다

**보안**

- [ ] 모든 API에 인증이 있고, 데이터 소유자 확인을 한다
- [ ] 입력값을 `zod` / `pydantic` 등으로 검증한다
- [ ] 문자열로 조립한 SQL, 검증 없이 쓰인 MongoDB 쿼리 값이 없다
- [ ] `innerHTML`·`dangerouslySetInnerHTML`·`|safe` 사용이 없다
- [ ] 비밀번호는 해시로 저장하고, 운영 환경의 디버그 모드가 꺼져 있다
- [ ] CORS 허용 도메인이 명시되어 있다
